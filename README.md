# docwhere

フォルダ以下の PDF・Word・Excel・PowerPoint・HTML・テキストを**節単位**で全文検索し、該当箇所をそのまま開く CLI。社内 wiki（Confluence）も wiki 自身の検索を通して同じ形で引ける。
エージェントからは Agent Skills 形式のスキル `office-search`（[skills/office-search/SKILL.md](skills/office-search/SKILL.md)）経由で使う。

```
> docwhere search config 設定コマンド --in D:\docs
 1. 運用マニュアル.docx  3 コマンド > 3.2 config コマンド  (2026-08-01)
    config は設定ファイルを読み込み、値を検証する。
    D:\docs\運用マニュアル.docx
 2. 設計書_v1.pdf  2 CLI > 2.1 config  p.45  (2025-03-10)
    config コマンドは設定値を検証する
    D:\docs\旧版\設計書_v1.pdf
    ! newer version: 設計書_v2.docx
> docwhere show 1     # 節の全文
> docwhere open 1     # Word がその段落を選択した状態で開く
```

## インストール

```
uv tool install -e .
```

## コマンド

| コマンド | 内容 |
|---|---|
| `search TERM... [--in DIR] [--all] [--ext pdf,docx] [--json] [--wait SEC \| --wait-all]` | 検索。実行前にフォルダの変更分だけインデックスを更新する。読む量が多いときは最大 20 秒（`--wait`）待ってから、そこまでに読めた分で答え、残りは裏で読み続ける。`--wait-all` は全部読み終わるまで待つ |
| `show N [-C K]` | 直前の検索の N 件目の節を全文表示（`-C` で前後の節も） |
| `show --id ID [-C K]` | `search --json` の `id` で節を全文表示。複数の検索が並行していても番号がずれない |
| `open N` | N 件目を該当箇所で開く |
| `view [N...] [-C K] [-P K] [--quote Q [--note T]] [--figure F [--note T]] [--answer A] [--title T] [--no-open]` | 直前の検索結果を 1 枚の HTML でブラウザの新しいタブに表示（`--title` は質問文で、タブ名になる）。節の抜粋（検索語を強調）、PDF はページ画像付き（`-P` で前後 K ページも）。`--quote` に回答の根拠の文を渡すと、その文を枠と太字で示し、検索語は下線に下げる。`--answer` は先頭に出す一行の回答。`--figure` は図そのものを根拠にするときに使い、図の見出し（`図2 再試行の流れ`）か `p.12#2`（12 ページの上から 2 つ目の図）で指定すると、その図を丸で囲んで拡大する（図は文字ではなくページ上の画像・線のまとまりから探すので、文字を含まない図でもよい）。`--quote` / `--figure` の直後の `--note` には、その箇所が示していることを書く。`--note` があると根拠を番号付きの手順として並べ、最後に「つまり〈--answer〉」で締める（「ここに A、別のページに B、つまり C」）。`search --view` でも同じオプションが使える |
| `viewer window\|browser\|status` | ビューを docwhere の専用ウィンドウで開くか（既定）、ブラウザで開くか。`view --browser` で 1 回だけブラウザで開く |
| `viewer pdf <プログラム> <引数...>` / `viewer pdf auto`（ウィンドウ右上の「設定」からも変えられる） | 「PDF アプリで開く」で使うアプリ。引数の `{page}` にページ番号、`{file}` に PDF のパスが入る（例: `viewer pdf "D:\Tools\SumatraPDF\SumatraPDF.exe" -reuse-instance -page {page} {file}`、Acrobat なら `/A page={page} {file}`）。シェルを通さずに起動する。`auto`（既定）は Acrobat があれば Acrobat、なければ既定のアプリ（ページ指定なし） |
| `clean` | 保存したビュー、snap の画像、Word / PowerPoint から書き出した PDF をすべて削除（普段は自動で間引かれる） |
| `snap N` / `snap --id ID [--term T] [-P K] [--quote Q]` | PDF のヒットしたページ（と前後 K ページ）を、検索語と回答の文を強調した PNG に保存してパスを表示 |
| `index DIR... [--rebuild] [--timeout SEC]` / `index --stop` | インデックスを明示的に作成・再作成（読み終わるまで待つ） / 裏の読み込みを止める |
| `exclude DIR [PATTERN...] [--remove \| --clear]` | DIR の下のフォルダやファイルを、インデックスと検索から外す（パターンなしで一覧）。下の「除外」 |
| `doctor [DIR...] [--skill SKILL.md] [--no-office]` | この PC で動くかの確認。下の「動作確認」 |
| `status [--errors]` | インデックス済みフォルダ、各フォルダの除外パターン、読めなかったファイル |
| `wiki add NAME URL [--space KEY]` / `wiki list` / `wiki remove NAME` | 検索する wiki の登録（下の「社内 wiki」） |
| `wiki check [NAME] [--term T]` | wiki に届くか、バージョン、REST API の有無、スペース、試しの検索の結果 |
| `wiki spaces [NAME] [--json]` | ログインせずに見られるスペースのキーと名前の一覧 |
| `wiki search TERM... [--all] [--wiki NAME] [--space KEY] [-n K] [--json]` | wiki の検索。ヒットしたページを節に区切り、合う節と前後の文、節へのリンクを出す |
| `wiki show N [-C K] [--whole]` / `wiki open N` | 直前の wiki 検索の N 件目の節を表示 / ブラウザで開く |
| `wiki view [N...] [--quote Q] [--answer A] [--title T]` | 直前の wiki 検索の結果を `view` と同じ画面で表示。回答の根拠の文に枠を付け、ページはボタンでブラウザで開く。`wiki search --view` でも同じ |

複数の TERM は OR（`--all` で AND）。見出しに語を含む節、複数の言い換えに当たる節が上位に来る。

## 対応形式と「該当箇所」

| 形式 | 検索単位 | 位置 | open |
|---|---|---|---|
| PDF | しおりがあれば章ごとのページ、なければ文字の大きさ・太字・「第N章」から推定した節 | p.N | Acrobat で該当ページ |
| docx / docm / doc | 見出しで区切った節。表は行ごとに見出し行のラベル付き | 節の見出し | Word で該当段落を選択 |
| xlsx / xlsm / xls | シートの行（見出し行付き） | Sheet!D5 | Excel で該当セルを選択 |
| pptx / pptm / ppt | スライド（ノート含む）。表は行ごとに見出し行のラベル付き | slide N | PowerPoint で該当スライド |
| html / htm | 見出し（h1〜h6）で区切った節。表は行ごとに見出し行のラベル付き。スクリプト・スタイルは読まない | 節の見出し | 既定のアプリ |
| txt / md / csv / log など | md は見出し、他は一定量 | L行 | VS Code で該当行 |

- .doc / .xls / .ppt は Office（COM）で新形式に変換してから読む。変換中のマクロは強制無効。Word の「開くときにリンクを更新する」は開く間だけ切る（他ファイルへのリンクを含む文書で確認ダイアログが出て止まるため。設定は元に戻す）。パスワード付きの .doc / .xls は読めないファイルとして扱う（.ppt は未検証）。
- ファイルは別プロセスで 1 件ずつ読み、1 件に 180 秒（`index --timeout` で変更可）以上かかったら打ち切って読めないファイルに入れ、残りを読み続ける。Office の変換で止まった場合は、変換のために起動した Word / Excel / PowerPoint ごと終了する（PowerPoint は 1 つしか起動できないため、利用者が先に開いていたときはそれを使い、終了させない）。打ち切ったファイルは、ファイルが変わるか docwhere の読み取り処理が更新されたときに読み直す。
- 新しいフォルダや変更の多いフォルダを検索すると、読み込みは別プロセス（ウィンドウなし）に任せ、検索は最大 20 秒待ってからそこまでに読めた分で答える。読み終えていないときは、結果の最後（`--json` では毎回ある `reading`、`--view` ではページ上部の帯）に「何件中何件を読んだ時点か」「残りの形式」「残り時間の目安」と、全件から探す方法を出す。裏の読み込みは 1 つだけで、フォルダを順に読み、終われば自分で終了する。数秒ごとに生存を記録し、途切れたら次の検索が引き継ぐ。進み具合は `status`、停止は `index --stop`。読み込みの記録はインデックスの横の `reader.log`。
- インデックス作成中の進捗は標準エラーに出す。端末では 1 行を書き換え、端末でないとき（agent やスクリプトから実行したとき）は 10 秒ごとに、件数・速度・残り時間の目安と、時間のかかっているファイル名を 1 行で出す。途中で止めても読み終えた分は 5 秒ごと（または 50 件ごと）に保存してあり、次回はその続きから読む。
- `open` で開く文書のマクロは、ダブルクリックで開いたときと同じく Office のセキュリティ センターの設定に従う。
- 展開後のサイズが 1 GB を超える Office ファイル（zip 爆弾）は読まない。文書中の制御文字は取り除いてから保存・表示する。
- 画像だけのスキャン PDF は読めない。検索結果の JSON の `unreadable` と `status --errors` に毎回出る。
- ファイル名から版違い（`_v1.4` / `_第2版` / `_最終` / `- コピー`）を同じ文書とみなし、古い版には `newer_version` を付けて順位を下げる。日付は版とみなさない（議事録などを別物として扱うため）。

## 動作確認（doctor）

`docwhere doctor` は、テストでは確かめられない、その PC の環境に左右される部分を試して、1 項目 1 行（`ok` / `FAIL` / `--`）で出す。出力をそのまま貼れば状況が伝わる。

- インデックスの保存先に書き込めるか、日本語の部分一致検索（SQLite FTS5 の trigram）が使えるか
- Word / Excel / PowerPoint で小さな .doc / .xls / .ppt を作り、本番と同じ経路で読めるか。1 つ 60 秒で打ち切り、止まったら Office ごと終了させる（Word の文書には他ファイルへのリンクを入れてある）。`--no-office` で省く
- 裏の読み込みがコマンドの終了後も動き続けるか。1 回の実行では自分の終了後を見られないので、確認用のプロセスを残し、次に `doctor` を実行したときに結果を出す（1 回目は `--`）
- ビューアのウィンドウ（pywebview と WebView2 Runtime）が使えるか
- SKILL.md の見出しがエージェントに読み込める形か（name とフォルダ名の一致、description の長さと書き方）。`--skill` でエージェント側にコピーした SKILL.md を渡すと、同じ名前のフォルダのリポジトリ版と食い違っていないかも見る
- `DIR` を渡すと、そのフォルダの変更確認（検索のたびに答える前にかかる時間）を測る

## 除外

古い版やバックアップのフォルダを、インデックスと検索から外せる。

```
docwhere exclude "D:\docs\設計" 旧版 "*_bak*" 設計書/archive
docwhere exclude "D:\docs\設計"            # 設定中のパターンの一覧
docwhere exclude "D:\docs\設計" --remove 旧版
```

- `/` を含まないパターンは名前で、どの深さのフォルダ・ファイルにも当たる（`旧版`、`*_bak*`、`*.log`）。`/` を含むパターンは DIR からのパス。大文字と小文字は区別しない。名前の一部に当てるときは `*旧*` のように書く。
- パターンは DIR に対して保存し、DIR の下のどのフォルダを検索しても効く（親フォルダでも、サブフォルダでも）。保存先はインデックスで、対象のフォルダには何も書かない。
- 検索のたびに、効いたパターンと、それで外したフォルダ・ファイルの数を出す（標準エラーと `search --json` の `excludes`。サブフォルダだけを検索したときも、親フォルダに設定したパターンを含めて数える）。除外したことを忘れて、答えがヒットから漏れているのに気づかない事態を避けるため。検索したフォルダそのものが除外されているときは `excluded_roots` に出る。
- 追加すると、当たるファイルはその場でインデックスから消える。外したパターンのファイルは、次の検索か `index` で読み直す。
- `status` に各フォルダのパターンと、そのフォルダを前回インデックスしたとき（検索を含む）に外したフォルダ・ファイルの数が出る（外したフォルダの中身は数えない。サブフォルダだけを検索したときは数えない）。`index --rebuild` ではパターンを残し、`forget` ではパターンも消す。

## 資料の地図とメモ（notes.csv）

`%LOCALAPPDATA%\docwhere\notes.csv` に「どのフォルダに何の資料があるか」と「この話はこの資料のここ」を書いておくと、
スキルが質問に応じて検索するフォルダを選び、メモの場所から先に確かめる。手で編集しても、エージェントに
「〜は〜に書いてあるって覚えておいて」「資料の地図作って」と頼んでもよい。docwhere 本体はこのファイルを読まない。

```csv
path,section,kind,note
D:\proj\docs\仕様書\通信,,仕様書,通信 プロトコル コマンド
D:\proj\docs\設計書,,設計書,
D:\proj\docs\仕様書\通信\通信仕様_v2.docx,3.2 通信パラメータ,仕様書,タイムアウト 再送回数
```

## 社内 wiki（Confluence）

Confluence（Server / Data Center）を、ログインせずに見られる範囲で検索する。ページを手元に写さず、
質問のたびに wiki 自身の検索を呼び、返ってきたページだけを読んで節に区切る。権限と内容の新しさは wiki 側の
ものがそのまま効き、サーバーへの負荷は 1 回の質問で数リクエストに収まる。

```
> docwhere wiki add team http://wiki.example:8090 --space OPS
> docwhere wiki check team --term タイムアウト     # 届くか、REST API があるか、日本語で当たるか
> docwhere wiki search 接続タイムアウト 既定値
 1. 接続設定 > タイムアウト  [team OPS]  2026-01-05
    項目: 接続タイムアウト / 既定値: 30 秒
    http://wiki.example:8090/display/OPS/接続設定#接続設定-タイムアウト
```

- `wiki view` は手元の資料と同じ画面（根拠の枠、根拠の一覧、引用のコピー）で結果を見せる。表示するページだけを読み直し、`wiki search --view` なら読み直さない。ウィンドウから開けるのは登録した wiki のページだけ。
- REST API があれば CQL 検索 1 回で本文ごと受け取る。無い・無効なサーバーでは、サイトの検索結果ページから上位のページを開き、本文（`main-content`）だけを読む。どちらの読み方も、Confluence の応答を模したテスト用のサーバーで確かめている。版による画面や API の違いはありうるので、初めてつなぐサーバーでは `wiki check` で何が使えるかを確かめる。
- docwhere がネットワークを使うのは `wiki` コマンドだけで、接続先は `wiki add` した URL だけ。ほかのサイトへの転送はたどらず、1 応答 16 MB、20 秒で打ち切る。ページの HTML は文字として読むだけで、スクリプトは実行しない。`wiki open` が開くのも登録した wiki のページだけ。
- 登録内容はインデックスの横の `settings.json` に入る（本人以外が書き込めるフォルダでは読まない）。手元に残るのは直前の検索結果の一覧（`last_wiki.json`）だけ。
- ヒットするかどうかは wiki の検索しだい。古いサーバーは、管理画面のインデックスの言語が日本語でないと日本語がうまく当たらないことがある。添付ファイルとマクロで差し込まれる内容は読まない。

## 画面に出る名前を変える

人に画面を見られる環境で、ツール名を出したくないとき用。

- **ビューアのウィンドウ名**（タイトルバーとタスクバー）：既定は「Reference」でツール名は出ない。変えるときは `docwhere viewer title "好きな名前"`。ページのタイトル（ブラウザで開いたときのタブ名）は質問文だけ。
- **スキル名**：既定の `office-search` にもツール名は入っていない。変えるときは `skills/office-search/SKILL.md` 先頭の `name:` とフォルダ名を同じ名前にする。
- **コマンド名**（ターミナルに出る `docwhere ...`）：`pyproject.toml` の `[project.scripts]` の `docwhere = ...` の左側を新しい名前にして `uv tool install -e . --force` で入れ直し、`SKILL.md` の中の `docwhere` をすべて新しい名前に置き換える。
- 内部の名前（保存先 `%LOCALAPPDATA%\docwhere\`、プロセス、パイプ名）は画面に出ないので変えなくてよい。

## 設計メモ

- `view` の HTML はインデックスと同じフォルダの `views\` に質問ごとの別ファイルとして保存するので、前の質問のタブは開いたまま残る。`views\index.html` が最近の質問と回答の一覧。
- ビューの中身は形式で変わる。PDF はページ画像。Word / PowerPoint は Office（マクロ強制無効の別インスタンス）で PDF に書き出してからページ画像にし、書き出した PDF はインデックスと同じフォルダの `renditions\` に保存して使い回す（Office がなければテキスト表示）。Excel はヒットした行の前後を見出し行付きの表で出す。
- `view` は既定で docwhere の専用ウィンドウ（WebView2、pywebview）で開く。印刷されたページ番号が PDF のページ番号とずれている資料では、欄外の番号からずれを読み取って「p.120（印刷 118）」のように両方を出し、印刷ページ番号での移動もできる。PDF のしおりから目次と現在位置の見出しを出す。ページの表示サイズは「全体」（ページ全体を画面の高さに収める）と 60〜250% の拡大縮小（キーは + / - / 0）で変えられ、拡大時はその倍率でページを描き直す。選んだサイズは次回も引き継ぐ。拡張機能・閲覧履歴・同期のあるブラウザを通さず、ポートも開かない。ウィンドウでは、PDF の任意のページへ送る（← →）・PDF 内の参照リンクをたどる（Backspace で戻る）、Acrobat / Word / Excel で該当箇所を開く、引用をコピーする、常に手前に表示する、ができる。ページ自体はスクリプトを CSP で禁止した静的 HTML のままで、操作用のスクリプトはウィンドウが外から注入し、Python とは pywebview の JS ブリッジで直接やり取りする。ブリッジは、docwhere が保存時に署名したページ（鍵ファイルから作る HMAC を `<ページ>.sig` に置く）を表示している間だけ応じ、それ以外のページや保存後に書き換えられたページでは操作用のスクリプトを入れず、呼び出しも拒否する。応じる内容は、インデックスにあるファイル（と docwhere が作った PDF）のページ画像・リンク一覧・目次、インデックスにあるファイルを開く、クリップボードへのコピー、手前に固定、表示サイズと設定（ウィンドウ名・開き方・PDF アプリ）の読み書き、PDF アプリの試し起動。PDF アプリにはシェルやスクリプト実行系（cmd、PowerShell、mshta など）を指定できず、設定ファイルを直接書き換えても起動の直前に確かめて無視する。鍵ファイルは本人が所有し本人だけが読み書きできるもの以外は使わない。インデックスのフォルダ（`DOCWHERE_DB` の置き場所）に本人以外が書き込める場合は、専用ウィンドウも鍵ファイルも使わずブラウザで開く。2 回目以降の `view` は、起動済みのウィンドウに名前付きパイプ（鍵ファイルで認証）でページを渡す。ウィンドウの位置と大きさは次回も引き継ぐ。pywebview が使えない環境ではブラウザで開く。
- ビューの「PDF をこのページで開く」は、ブラウザが巨大な PDF を丸ごと読み込んで遅くならないよう、該当ページの前後 10 ページだけを抜き出した PDF（元のページ番号のラベル付き）を開く。ブラウザで開くときだけ作り、`renditions\excerpts\` に保存して使い回す（専用ウィンドウではページ送りがあるので作らない）。全体を開くリンクも横に残す。
- ビューと snap の画像は、新しく書き出すたびに古いものを間引く。直近の分（ビュー 10 件、画像 5 件）は開いているタブを壊さないよう必ず残し、それより古いものは件数（50 / 30）、経過日数（14 日 / 1 日）、合計サイズ（200 MB / 100 MB）のどれかを超えたら消す。値は `viewer.VIEW_RETENTION` / `SNAP_RETENTION`。文書の文字列はすべてエスケープし、画像は data: URI で埋め込み、CSP でスクリプトと外部への通信を禁止しているので、文書の中身が実行されたり外に出たりしない。
- インデックスは `%LOCALAPPDATA%\docwhere\index.db`（`DOCWHERE_DB` で変更可）。SQLite FTS5 の trigram トークナイザで、日本語も形態素解析なしで部分一致する。2 文字以下の語は LIKE で走査。
- 文字は NFKC 正規化して保存・検索するので、全角/半角の違いでは取りこぼさない。
- 更新判定は mtime + size。抽出処理を変えたら `extractors.EXTRACTOR_VERSION` を上げると、既存インデックスが自動で再抽出される。
- 新しい形式は `src/docwhere/extractors/` にモジュールを足し、`@register(".ext")` を付けて `_MODULES` に登録する。
